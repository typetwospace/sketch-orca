# orca-cli

The Rust program, sketch-orca-rs: sketch-orca's commands, intake, presets stage, declines and crash result.

The command line of the Rust translation: the program `sketch-orca-rs`, a separate program from the C++ `sketch-orca` of `cli/`, under the same licence. It is to run the protocol's commands (`version`, `config-def`, `run`) with the intake the C++ front end has, decline a job it cannot do yet before it writes any output (result code `not-ported`, exit -8, with a list of what is missing), and on a crash write the `internal-error` result and exit with -1.

What it answers so far:

- `help`, `--help`, `-h`: `cli/main.cpp`'s usage text on stdout, exit 0. No command: the usage on stderr after `sketch-orca: no command`, exit -2; an unknown command, an option a command does not take, a missing or repeated option or a missing value: the same message `cli/main.cpp` gives, the usage, exit -2.
- `version` (and `--version`): the C++ program's `version.json` line (`engine`, `engineVersion` from the workspace's version, `orcaVersion` 2.4.2, `orcaTag` v2.4.2, `orcaCommit` 8500fcdccaa10b5099ac20d252af3a7c560046f1), plus `implementation: "rust"` (`src/version.rs`).
- `config-def --out <file>`: the same file as the C++ program's, byte for byte (`parity/goldens/front/config-def.json`, with the engine version of the build): every setting of orca-config's definitions but SLA's, `coNone`'s and the obsolete keys, then the obsolete keys (`src/config_def.rs`). It is written as `cli/common.cpp`'s `write_file_atomic` writes it (`<file>.tmp`, then a rename; `src/files.rs`), with the same messages and exit -13 when it cannot be.
- `run --job <file> --out <file> [--progress <file>]`: its command line is checked as `cli/main.cpp` checks it, and a command line it does not take still gets an `invalid-params` result at `--out` when one can be written there. The run follows `cli/run.cpp`'s `run_job` and `run` up to the reading of the model: the job is read and checked as `cli/job.cpp` reads it, in the same order and with the same messages (`src/job.rs`); the run's files (the job, every absolute path it names, the result, the progress file and the outputs with the files they are written through) are told apart as the C++ tells them apart (`src/result.rs`, `src/paths.rs`: Boost.Filesystem's `is_absolute`, and two names of one file on Windows); the result and the progress file are written as the C++ writes them (`src/result.rs`). Then come the presets stage and the model's file, below. Every command line and job the C++ refuses up to there gets the same result, exit code, warnings and progress file; the corpus holds the C++ result of each such refusal (`parity/goldens/front/intake/`, `tests/intake.rs`) but the thumbnails' internal error and some forms of `setting-invalid` (`src/presets.rs`); a refusal the C++ makes later, from the reading of the model on, comes from a step that is not certified, so such a job is declined instead.
- The presets stage (`src/run.rs`, `src/presets.rs`, on Orca's configuration in `src/config.rs`), as `cli/run.cpp` and `cli/presets.cpp` do it, step for step: the progress line `presets` (3); the resources folder must have a profiles folder (`environment`), and the work folder and its `orca-data` folder are made (`output-failed`); the machine, process and filament presets are read (`file-not-found`; `preset-invalid` for a file that is not JSON or not an object, of the wrong type, from elsewhere or with a value Orca cannot read; `not-fdm`; a value of no form Orca reads is skipped with `preset-value-skipped`, an enum value it does not know substituted with `setting-substituted`), checked against each other (`process-not-compatible`; a filament that does not match is a warning) and merged, the job's overrides applied (`setting-invalid` for a key Orca does not have or a value it cannot read) and the whole checked as Orca checks it (`config-invalid`, the flushing volumes' inputs included), with the C++ warnings in the same order; then the progress line `model` (8) and the model's file (`file-not-found`). A preset that has no `compatible_printers` or `compatible_prints` list but a condition needs Orca's placeholder parser, which is not ported: the job is declined there, naming the family `preset-conditions` besides the job's own.
- The decline (`src/decline.rs`): a job that gets past the model's file is checked against the families `parity/parity.json` certifies. The families it reaches are its command's (model-load and placement, then info, slice-mesh, and for a slice the steps every slice runs) and, for a slice, those its settings turn on: the wall generator, each surface's infill pattern, supports, raft, ironing, fuzzy skin, the prime tower (Orca's `has_wipe_tower`: with more than one filament, smooth timelapse, or clumping detection with an exclusion area of more than two points, counted as Orca's reader splits them) and Z contouring, read as the corpus reads them (`scripts/lib/parity/corpus.ts` `familiesFor`: the job's overrides, then its flattened process, machine and filament presets, then Orca's defaults from orca-config), and again for each object's overrides and each height range's. Presets it cannot read leave the settings unknown, and the job then reaches every family a setting can turn on. A job that reaches a family this program does not do (`decline::PORTED` and certified), which for now is every `info`, `layers` and `slice` job, gets result code `not-ported`, exit -8 and `missing`, the families in parity.json's order (`protocol/examples/result-not-ported.json`, a slice with Orca's default settings), before any output is written; the work folder and its `orca-data` folder are made by then, as the C++ makes them. parity.json is read at build time (`include_str!`). `parity certify` fails when a run of a corpus job, example or refusal that reaches an uncertified family is not declined naming it. A declined run passes no family, and a run declined although the C++ run ended within what this program does itself (no stage past `presets`, or a missing model file) is wrong in itself.
- A crash (`src/crash.rs`): an unhandled exception, an `abort` or a panic writes the `internal-error` result the C++ writes ("the engine crashed (<what>) during '<stage>', in Orca's code"), and the process ends with -1; no system crash dialog is shown. `SKETCH_ORCA_TEST_CRASH=<stage>` crashes with an access violation when the run reaches that stage, `<stage>:abort` with an abort, as in the C++ program, for the stages this program reaches (`job`, `presets` and `model`); `<stage>:panic` (this program only) with a panic; the point `decline` (this program only) is just before a decline is written, and its result names the stage `model`.

On Windows stdout and stderr end their lines with a carriage return and a line feed, as the C++ program's text-mode streams do; files are written as bytes.

The modules: `main.rs` (the command line), `common.rs` (the failures and their exit codes, `cli/common.hpp`), `files.rs` (reading files, and writing them whole through `<file>.tmp`), `paths.rs`, `job.rs`, `result.rs` (results, progress, the run's files and `run_job`), `run.rs` (the work after the job is read: the folders, the presets stage, the model's file, the decline), `presets.rs` (the presets stage), `config.rs` (Orca's configuration: reading a value, the extruder variants, normalising, the defaults and Orca's check), `decline.rs`, `crash.rs`, `version.rs` and `config_def.rs`.

`tests/version.rs`, `tests/config_def.rs`, `tests/intake.rs`, `tests/decline.rs` and `tests/crash.rs` run the built program hidden (no console window) and compare what it writes with the front end's goldens and `protocol/examples/` (`tests/common/mod.rs` is what they share); `tests/intake.rs` fails when a refusal case of the corpus whose only family is `intake` has no test there. The modules hold their unit tests. `bun scripts/orca.ts parity certify` runs the program on the whole corpus (the repository's `README.md`).

Part of the Rust translation of sketch-orca (the workspace in the repository root; see the
repository's `README.md`, `BUILDING.md` and `CONTRIBUTING.md`). Licence: AGPL-3.0-only.

Build it with `bun run rs:build`; the program is `target/debug/sketch-orca-rs.exe` (`bun scripts/rust.ts build --release` builds `target/release/sketch-orca-rs.exe`).

Carries Boost.Filesystem code in `src/paths.rs` (Boost Software License 1.0; the repository's `NOTICE`). `src/config.rs` and `src/presets.rs` carry OrcaSlicer code (AGPL-3.0); each says which code from which file in its `Carries OrcaSlicer code` block.

## Rules

- The usage text, the exit codes and the result files follow `cli/` and `protocol/`; a difference is a bug in one of them.
