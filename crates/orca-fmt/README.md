# orca-fmt

printf, to_chars, iostream double output, strtod, stod and from_chars parsing, and the C stdio and scanf of admesh's STL reader, as the C++ engine gets them.

Number formatting and parsing that gives the bytes the C++ engine's runtime gives (MSVC 14.42's standard library and the static UCRT, in the "C" locale):

- `printf`: `sprintf`, `snprintf` and `sprintf_s` (`_snprintf_s`), written from the C standard (`d i u x X o c s e E f F g G a A %`, every flag, width, precision and `*`, and the UCRT's length modifiers) with the UCRT's choices: its spelling of infinities and NaNs (`inf`, `nan(ind)`, `nan(snan)`), exact decimal expansion at every precision, and its two error behaviours (the standard family prints an invalid conversion as text; the secure one fails).
- `to_chars`: `std::to_chars`, translated from microsoft/STL: Ryu for the shortest round-trip form, Ryu printf for the precision forms, and the hexadecimal forms; integers in every base.
- `ostream`: `std::ostream << double` (and `float`, widened) as MSVC's `num_put` builds it: the printf format from the stream's flags, then the locale's decimal point, grouping and fill; and `std::to_string(double)`.
- `parse`: `std::from_chars`, translated from microsoft/STL, for integers and floating values; the UCRT's `strtod`, `strtof`, `atof`, `strtol`, `strtoul`, `strtoll`, `strtoull`, `atoi`, `atol` and `atoll` around it, with the three places where the UCRT reads a number otherwise than the STL (a digit after the 768th ignored; an exponent above 5200 or below -5200 infinite or zero before the digits' place is added; a tie with eight or nine decimal places rounded up, not to even) and the UCRT's NaN spellings, all found by black-box tests of the UCRT (the `ucrt_` tests below; `parse.rs`'s header gives the provenance); and the STL's `std::stod`, `stof`, `stoi`, `stol`, `stoul`, `stoll` and `stoull`.
- `istream`: `std::istream >> double` and `>> int` in the classic locale, translated from MSVC 14.42's `num_get` (`xlocnum`): the sentry's skipping of white space, the characters `_Parse_fp_with_locale` and `_Parse_int_with_locale` take (768 significant digits, the last one sticky, the exponent held to 1100, a hexadecimal form after `0x`), then `strtod` or `_Stolx` on them, with the stream's state after (`fail` and nothing stored at the end of the text; 0 stored and `fail` for a field that does not parse; `LONG_MAX` or `LONG_MIN` and `fail` on overflow). orca-config reads option values through it. The probe does not record `num_get` yet (`parity/HAZARDS.md`, "Formatting and parsing"), so only unit tests and orca-config's round trips of the probe's defaults hold it.

- `stdio`: the UCRT's `FILE` streams for reading (`fopen` in `"r"`, `"rt"` and `"rb"`, `freopen`, `getc`, `ungetc`, `fgets`, `fread`, `fseek`, `ftell`, `rewind`, `feof`) as admesh's STL reader and the OBJ reader use them, and C's `stdout` (`stdout_write`, with a settable sink), written from the C standard and black-box tests of the UCRT (o2-mesh, 2026-11-07). A text stream reads what the UCRT's text mode gives: CR LF as LF, any other CR as itself, the first Ctrl-Z as the end. `stdout` is a text stream too (the engine never sets it to binary), so on Windows each line feed `stdout_write` gets reaches the process's output as CR LF; a sink gets the bytes as `printf` wrote them.
- `scanf`: the UCRT's `fscanf` and `sscanf` for the directives admesh's reader passes (white space, literals, `%s` and `%[...]` with widths, `*`, `%f` and `%lf`), with the UCRT's return counts and its input and matching failures: a number cut off by the end of the input is an input failure (`EOF`), one cut off by another character a matching failure that leaves the characters read before lost; `%f` drops a NUL or 0xFF that ends a number; `%f` stores `strtof` of the characters it read, `%lf` `strtod`. A `%s` or `%[` that would overrun its buffer stops with `Overflow` instead (the CR box, `parity/HAZARDS.md`).

The Microsoft STL code is under Apache-2.0 WITH LLVM-exception (`licenses/Apache-2.0.txt` and `licenses/LLVM-exception.txt`); each file that carries it says what it carries and from where in its `Carries` block.

`tests/fmt.rs` holds the crate to the UCRT linked into the test program: printf against `__stdio_common_vsprintf` and `__stdio_common_vsnprintf_s` on millions of seeded values and formats, the parsers against the UCRT's own functions (exact ties and long inputs among the texts), the `ucrt_` tests that find each of the UCRT's own ways of reading a number in the UCRT itself (`ucrt_rounds_some_ties_up`, `ucrt_ignores_digits_after_the_768th`, `ucrt_exponent_limit`, `ucrt_nan_spellings`), `ostream` against the UCRT's `sprintf_s` of MSVC's format, and round trips of every form; and to 25 streams that a program built with MSVC 14.42 printed. The crate's `to_chars`, `from_chars`, `sto*`, `ostream` and `to_string` were also compared with such a program on 300,000 seeded cases of each kind, with no difference.

`tests/scanf.rs` holds `stdio` and `scanf` to the UCRT linked into the test program, through `__stdio_common_vfscanf` and `__stdio_common_vsscanf` and the UCRT's `fopen`, `getc`, `fgets`, `fread`, `fseek` and `ftell`, on text streams, binary streams and strings: the `%f` grammar on every prefix of each spelling (`ucrt_float_grammar`), every byte value after each prefix (`ucrt_stop_bytes`), `%f` against `strtof` and `%lf` against `strtod` on 34,410 numbers with the UCRT's ties, digit and exponent limits and NaN payloads (`ucrt_scanf_float_is_strtof`), the admesh formats on fixed and generated input (`ucrt_directives`, `ucrt_directives_generated`), the text mode's line ends across the UCRT's 4096-byte pieces (`ucrt_text_mode`) and a binary stream's seeks and reads (`ucrt_binary_stream`).

`tests/probes.rs` replays every record of the probe program's `fmt.sop1` (`parity/SOP1.md`): `snprintf`'s text and count, `to_chars` with its `errc`, `ostream` output under every flag, width, fill and locale, `to_string`, and the parsers' values, lengths and statuses, byte for byte; the committed subset by default, the full set with `SKETCH_ORCA_PROBES_DEEP` (`crates/orca-probe/README.md`). It replays `cstdio.sop1` too (o2-mesh, 2026-11-07): CSCN, `sscanf` of the static UCRT with each format admesh passes, on every spelling of a number and seeded STL text, the count and every byte of every argument; and CFIL, scripts of `getc`, `fgets`, `fscanf`, `fread`, `ftell`, `fseek`, `rewind` and `feof` on files with each line end, Ctrl-Z, cut short or of random bytes, opened `"rb"`, `"r"` and `"rt"`. Every record of both sets matched on 2026-11-07. Where a text stream's `fread` is asked for 512 bytes or more at the stream's start, the UCRT reads the file straight into the caller's buffer and translates it there, leaving the file's raw bytes after what it returns; `stdio` writes only the bytes read, and the probe records only the items returned (C leaves the rest unspecified, and no reader looks at it).

Part of the Rust translation of sketch-orca (the workspace in the repository root; see the
repository's `README.md`, `BUILDING.md` and `CONTRIBUTING.md`). Licence: AGPL-3.0-only.

## Rules

- Engine crates format and parse numbers only through this crate; Rust's `format!("{}")` of a float is not `printf`, and `str::parse` is not `strtod`.
- Code translated from microsoft/STL keeps the STL's structure and names, function for function, so that it can be compared with the tag it came from (vs-2022-17.12).

None.
